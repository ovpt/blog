# iOS 安全研究进阶指南

适用设备：iPhone XS Max，A12，Lightning 接口。写这份指南时手机上的系统是 iOS 18.7.9。核对日期：2026-10-31（北京时间）。

实验文件都在同一目录的 `labs/` 里。每个实验只有一个通过标准。通过行出现之前，不要开始下一个实验，也不要为了它去搜索。

## 这份指南怎么替你挡噪声

- 一次只做当前实验。失败时只执行该实验里的「唯一修复」。修复一次仍然失败，把屏幕上的原文抄进 `labs/bug-note.md`，这一天就停。
- 命令在 Mac 的「终端」里执行。手机上的点击按中文系统写。手机是英文时，用括号里的英文，菜单位置不变。
- 指南核对时，这台手机能安装的最新正式版是 iOS 18.7.11（构建号 22H384，2026-10-26 发布）。软件更新若给出更高的 18.7 版本，装那个。不要打开测试版更新。
- 研究范围只有三样：这台手机、你用自己的 Apple ID 签名的 App、你在 Mac 上编译的公开源码。
- 本指南停在「能复现、能写进笔记」。它不包含把崩溃变成代码执行的步骤。

## 这台手机先认清的事实

iPhone XS Max 的芯片是 A12。公开的 checkm8 覆盖 A11 及更早的芯片，不包括这台手机。iOS 18.7 这一支也没有被本指南使用的研究用越狱环境。后面所有实验都在未越狱的系统上完成。

在这台手机上，内核、Wi-Fi 固件、SEP 看得到的崩溃栈不完整。能在几轮实验里看见真实安全边界的，是你自己的 App，以及 Mac 上编出来的 WebKit。原因和起步顺序写在并列的[早期漏洞研究方向](早期漏洞研究方向.md)。

你需要：

- 这台 iPhone，一根能传数据的 Lightning 线
- 一台能从 App Store 安装当前 Xcode 的 Mac。2026-10-29 的 Xcode 27.2 要求 macOS Tahoe 26.6 或更新。WebKit 主干自 2026-03 起要求 Xcode 26.2 或更新
- 一个 Apple ID。免费账号可以装你自己的实验 App，描述文件大约 7 天后失效。失效的表现和修复在 L2

## L0 记下版本，再更新

1. 打开「设置 > 通用 > 关于本机」（Settings > General > About）。
2. 把「名称」「iOS 版本」「型号名称」「型号号码」四行抄到 `labs/bug-note.md` 的日期下面。iOS 版本那一行要整行都抄，包括括号里的构建号。点一下版本号，构建号会显示出来。
3. 打开「设置 > 通用 > 软件更新」。
4. 页面给出比 18.7.9 新的 18.7 版本时，接通电源，连上 Wi-Fi，安装，等手机重启。
5. 重启后回到关于本机，把新的 iOS 版本整行抄在旧版本下面。

通过：笔记里有更新前、更新后两行版本。更新后的版本高于 18.7.9。

唯一修复：页面停在 18.7.9 并写着已是最新。先关掉 VPN（「设置 > 通用 > VPN 与设备管理」），回到软件更新页面向下拉。仍然没有新版本，就在笔记里写「当天更新页没有提供更高版本」，继续 L1。这种情况下，后面凡是要在手机上确认的结果，都只对你抄下来的这一版有效。

不要在这一步注册开发者计划，也不要改 Beta 开关。

## L1 检查 Mac

在 Mac 上把本仓库放在家目录：

```bash
mkdir -p ~/ios-research
git clone --depth=1 --branch cursor/ios-security-guide-c7ff https://github.com/ovpt/blog.git ~/ios-research/blog
bash ~/ios-research/blog/docs/ios-security/labs/preflight.sh
```

仓库已经在本机时，直接对这份副本里的 `docs/ios-security/labs/preflight.sh` 运行 `bash`，后面的路径同样换成你的副本。`clone` 若提示找不到这个分支，说明指南已经在默认分支上。去掉 `--branch cursor/ios-security-guide-c7ff` 再执行一次 `clone`。

通过：最后一行是 `PREFLIGHT_RESULT=all-pass`。

唯一修复：有 `FAIL` 时，只做该行文字里写的那一个动作，然后重新运行脚本。脚本没有写的安装方式不要做。`FAIL` 若只说 Xcode 低于 26.2，或可用空间少于 120 GB，L2 到 L16、L18、L19 继续；跳过 L17。

## L2 把实验 App 装到手机上

这一节同时打开开发者模式和签名。顺序不能换。

1. 用 Lightning 线连接手机和 Mac。手机解锁。
2. 打开 Xcode。菜单 Window > Devices and Simulators（窗口 > 设备和模拟器）。
3. 手机弹出「要信任此电脑吗」时点信任，输入密码锁。
4. 等到设备那一行不再显示 Preparing（正在准备调试器支持）。第一次可能要几分钟，让屏幕保持亮着。
5. 满 15 分钟仍是 Preparing：拔线，解锁手机，再插上，回到第 4 步。这是这一节的准备阶段修复，只用一次。
6. 手机打开「设置 > 隐私与安全性」（Settings > Privacy & Security），滑到底。打开「开发者模式」（Developer Mode）。按提示重启。重启后点「打开」，输入密码。
7. 列表里没有「开发者模式」：设备窗口还没配对完成，回到第 4 步。不要在设置里用搜索框找别的名字。
8. Xcode：File > New > Project。平台选 iOS，模板选 App，Next。
   - Product Name：`SecurityLab`
   - Interface：SwiftUI
   - Language：Swift
   - Storage：None
   - 测试和 CloudKit 相关的勾选都关掉
9. 存到 `~/ios-research/SecurityLab`。
10. 点左侧蓝色工程图标，选中 TARGETS 里的 SecurityLab，打开 Signing & Capabilities。
    - Team 选你的 Apple ID。列表是空的就点 Add an Account，用同一个 Apple ID 登录。
    - Bundle Identifier 改成 `com.` 加上你的名字再加 `.securitylab`。名字用小写英文字母。
11. 窗口顶部的运行目标选这台 iPhone 的名字，不要选任何 Simulator。
12. 打开仓库里的 `docs/ios-security/labs/ContentView.swift`，全选复制。在 Xcode 里打开同名文件，全选粘贴，保存。
13. 按 Run（三角形）。手机亮起时若要求输入密码，输入。

通过：手机上打开 SecurityLab，屏幕第一行是「点下面的按钮。一次只做一个实验。」

唯一修复，按你实际看到的那一句对上：

| 屏幕上的句子 | 动作 |
| --- | --- |
| Failed to register bundle identifier | Bundle Identifier 最后一段改成 `securitylab2`，再 Run |
| Untrusted Developer，或「不受信任的开发者」 | 手机「设置 > 通用 > VPN 与设备管理」，点你的描述文件，点信任，再在 Xcode 里 Run |
| 开发者模式那一行不存在 | 回到本节第 4 步，等设备窗口不再 Preparing |
| Signing requires a development team | Signing 页的 Team 重新选中你的 Apple ID |
| 编译错误里出现 actor、Sendable 或 main actor | 点蓝色工程，Build Settings，搜索 Strict Concurrency Checking，改成 Minimal。再搜索 Swift Language Version，改成 Swift 5。然后 Run |

免费描述文件大约 7 天后 App 会打不开。现象是一点图标就退出，或提示开发者证书不再受信任。修复只有一个：插上线，Xcode 里再按一次 Run。

## L3 看见沙盒

手机上点「1 沙盒读写」。

通过：日志里 `inside=` 后面是「成功」，`outside=` 后面是「失败」。`home=` 的路径里有 `Containers/Data/Application`。

唯一修复：`inside=` 是失败。在 Xcode 里确认运行目标是这台 iPhone，不是 Simulator，再 Run，再点一次按钮。

`outside=` 是「成功」时：把整段日志抄进 `labs/bug-note.md`，结论选「可复现的逻辑差异，准备提交」。这一天剩下的实验先不做。

## L4 看见明文网络被拒绝

手机连上能上网的 Wi-Fi。先点「2 加载 HTTPS」，再点「3 加载 HTTP」。

通过：日志里同时有 `load finished https://example.com/`，以及 `load failed domain=NSURLErrorDomain code=-1022`。`-1022` 是 App Transport Security 拒绝明文 HTTP 的错误码。

唯一修复：按钮 2 的失败码不是 `-1022`，也没有 `load finished`。这是网络没通。换一个 Wi-Fi 再点按钮 2。不要改 Info 设置。

确认 `-1022` 之后，再做一次开关，证明这个错误是你自己打开的策略：

1. Xcode 点蓝色工程，TARGET SecurityLab，Info。
2. 在 Custom iOS Target Properties 里点某一行右侧的加号。
3. 输入 `App Transport Security Settings`。没有这一项时输入 `NSAppTransportSecurity`。
4. 展开它，再点加号，选择 `Allow Arbitrary Loads`。没有这个名字时输入 `NSAllowsArbitraryLoads`，类型选 Boolean，值选 YES。
5. Run。点按钮 3。通过这一半：出现 `load finished http://example.com/`。
6. 把 `NSAllowsArbitraryLoads` 改回 NO。Run。点按钮 3。

通过：按钮 3 再次出现 `code=-1022`。YES 留在工程里时，后面的实验不能说明网络策略还在。

## L5 钥匙串的访问级别

点「4 钥匙串」。

通过：日志是 `keychain add=0 read=0 value=lab-secret`。`0` 是 `errSecSuccess`。写入时用的保护级别是 `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`：第一次解锁之后可以读，而且不会迁到另一台设备。

唯一修复：`add=-34018`。运行目标选成了 Simulator，或签名没成功。按 L2 的表格处理签名，运行目标改回这台 iPhone，再点一次。

## L6 消息桥只接受指定来源

这是后面 WebKit 阅读要用的同一类边界。Apple 在 iOS 18.7 这一支里修过「恶意网站访问本应属于其他来源的 script message handler」。这里先把检查做对，再在 L18 看别人的代码有没有同样的判断。

1. 点「5 本地消息桥」。网页里点 send。
2. 点「6 注入到 example.com」。

通过：日志里同时有这两行。

- `bridge host=lab.local body=clicked`
- `bridge ignored host=example.com body=injected`

`load finished` 可以同时出现，忽略它。

唯一修复：按钮 6 只有 `load failed`，没有 `bridge ignored`。手机没上网。用 L4 已经成功加载过 HTTPS 的那个 Wi-Fi，再点按钮 6。

若 `example.com` 那一行是 `bridge host=example.com` 而不是 `bridge ignored`：ContentView.swift 被改过。按 L2 第 12 步重新粘贴仓库里的文件，再 Run。

3. 没有 URL Types 这一块时，在属性列表点加号，键选 `URL types`（`CFBundleURLTypes`）。展开 Item 0，添加 `URL Schemes`，Item 0 的值填 `securitylab`。
4. Run。
5. 打开手机 Safari，地址栏输入 `securitylab://ping`。出现打开提示时点打开。

通过：SecurityLab 回到前台，日志有 `onOpenURL securitylab://ping`。

唯一修复：Safari 把这串文字当成了搜索。地址栏里必须有 `securitylab://` 这几个字符，不能只有 `securitylab`。

## L10 一次你自己触发的崩溃

Xcode 正在调试 SecurityLab 时，点「7 故意崩溃」。

通过：Xcode 停住，控制台文字里有 `SecurityLab deliberate crash`。

然后点 Xcode 的停止按钮，再 Run，把 App 拉起来。这个按钮只用于认识崩溃长什么样。后面的实验不要再点它。

唯一修复：点了按钮，手机黑屏回主屏幕，Xcode 没有停住。运行目标不是这台手机，或没有处于调试运行。Stop，选中 iPhone，Run，再点一次。

窗口 Devices and Simulators 里选中手机，点 Open Recent Logs（查看设备日志）。若列表里有 SecurityLab 的条目，打开它，确认同一句 `deliberate crash`。调试器已经接住崩溃时，这份设备日志可能不存在。控制台里的那一句就够通过。

## L11 拿到一份 sysdiagnose

用辅助触控，避免侧边按键按太久进入 SOS 倒计时。

1. 「设置 > 辅助功能 > 触控 > 辅助触控」，打开。
2. 点「自定顶层菜单」。点其中一个图标，选「分析」（Analytics），点完成。
3. 点屏幕上的辅助触控按钮，点「分析」。
4. 顶部出现开始收集的横幅。等到出现完成收集的横幅。可能要 10 分钟。期间可以锁屏，不要重启。
5. 「设置 > 隐私与安全性 > 分析与改进 > 分析数据」。用列表顶部的搜索框输入 `sysdiagnose`。没有搜索框就滑到 S 段。
6. 点今天这个文件，点分享，AirDrop 到 Mac。文件落在「下载」。

在 Mac 上：

```bash
ls -lh ~/Downloads/sysdiagnose_*.tar.gz | tail -1
tar -tzf ~/Downloads/sysdiagnose_*.tar.gz | head
```

第二条若因为多个文件报错，把 `ls` 打出的最新那个文件名替进去，不要加通配符。

通过：`tar` 打印出若干路径。到这里就停，不要在压缩包里翻找漏洞。

唯一修复：没有短振动、也没有横幅。再点一次辅助触控里的「分析」。若改用按键：同时按下音量加、音量减和侧边键，感到一次短振动立刻松开。出现 SOS 倒计时就马上松开，收集已经开始，不要继续按住。

做完可以把辅助触控关掉。

## L13 一次必定出现的 AddressSanitizer 报告

在 Mac 终端：

```bash
bash ~/ios-research/blog/docs/ios-security/labs/run_memory_labs.sh
```

脚本会编译 `labs/toy_overflow.c` 并运行。这个文件故意写了一个堆溢出，用来认识报告，不是 iOS 漏洞。

通过：输出里有 `PASS toy_overflow`，并且日志文件里同时有 `heap-buffer-overflow` 和 `WRITE of size 8`。终端若多打印一行 `Aborted`，同时退出码是 134，这是崩溃进程的正常提示，以 `PASS` 行为准。

打开脚本打印的那个 `.log`，对照这三句：

- `heap-buffer-overflow`：写过了堆块边界
- `WRITE of size 8`：这次写了 8 个字节
- `1-byte region`：分配时只要求了 1 个字节。输入前 4 个字节是 0，所以 `n` 是 0，分配大小是 `n + 1`

源码里对应的是 `parse` 中的 `memcpy`：拷贝长度用的是 `size - 4`，分配长度用的是另一个字段 `n`。两边没有比较。

把这三句和「练习崩溃，不提交」写进 `labs/bug-note.md`。这是笔记的样张。

唯一修复：输出是 `FAIL toy_overflow` 或 `FAIL toy_fuzz`。把该行原文留下，停止。不要改编译参数，不要换一个 sanitizer。

`PASS toy_fuzz` 也要出现。它说明同一份代码会被 fuzzer 在 20 秒内打到。fuzzer 找到崩溃后退出码不是 0，这是通过，不是失败。触发崩溃的输入写在 `~/ios-research/memory-labs/`，通过标准不要求打开这些文件。

## L14 把同一套动作用在你自己编译的 zlib

同一个脚本的后半段会克隆 [madler/zlib](https://github.com/madler/zlib.git)，用 AddressSanitizer 编译静态库，再跑 30 秒 `uncompress`。iOS 18.7.9 的安全说明里有 zlib，见 <https://support.apple.com/en-us/127111>。这一节不指望 30 秒撞上那个已修复的问题。

通过：`PASS zlib no-crash`，或 `PASS zlib asan-report`。

`no-crash` 时笔记写：流水线已跑通，这次输入没有错误。继续 L15。

`asan-report` 时：把含 `ERROR: AddressSanitizer` 的那一段抄进笔记，结论选「只有崩溃，还不能说明攻击者能控制什么」。当天停在这里，把报告读完再继续。不要根据这段日志写利用。

唯一修复：以 `FAIL zlib` 开头的那一行。按该行文字做。clone 失败只重试脚本里的那一条 `git clone`，第二次失败就保留 `PASS toy_fuzz`，改天再做 L14。

## L15 两个对照页：同源策略和 CSP

新开一个终端窗口：

```bash
bash ~/ios-research/blog/docs/ios-security/labs/serve_controls.sh
```

窗口保持开着。Mac Safari 打开：

- `http://127.0.0.1:8741/sop-control.html`
- `http://127.0.0.1:8741/csp-control.html`

通过：

- SOP 页面的文字以 `expected block:` 开头，并且含有 `SecurityError`
- CSP 页面的文字保持 `csp held`
- CSP 页面用「开发 > 显示网页检查器 > 控制台」能看到含 `Content Security Policy` 的拒绝记录

页面出现 `UNEXPECTED` 时：把整页文字抄进笔记，结论选「可复现的逻辑差异，准备提交」，停止后续实验。

唯一修复：页面一直是 `waiting for iframe`。example.com 没加载。用 L4 确认过能打开 HTTPS 的网络，刷新 SOP 页。

看完在服务器那个窗口按 Control-C。

这两页是对照。SOP 页的父页面和 iframe 不同源，脚本读 `contentDocument` 会被拒绝。CSP 页的策略是 `script-src 'none'`，内联脚本不会改写 `csp held`。后面读 WebKit 补丁时，回归测试也是在断言这一类句子。

## L16 读一笔已经公开的 WebKit 修复

```bash
cd ~/ios-research
git clone --filter=blob:none https://github.com/WebKit/WebKit.git
test -f WebKit/Tools/Scripts/build-webkit && echo PASS clone
```

`PASS clone` 出现之前不要做别的。克隆会很久。失败时只重试一次下面这一条：

```bash
rm -rf ~/ios-research/WebKit
git -c http.postBuffer=524288000 clone --filter=blob:none https://github.com/WebKit/WebKit.git ~/ios-research/WebKit
```

第二次仍失败：跳过 L16 和 L17，直接做 L18。

克隆成功后：

```bash
cd ~/ios-research/WebKit
git log --grep=308675 --oneline | head
```

`308675` 是 iOS 18.7.9 安全说明里的 WebKit Bugzilla 编号，内容是 CSP 没有被执行。公告：<https://support.apple.com/en-us/127111>。

有提交时，日志第一列是提交哈希。下面命令里的哈希换成那一列，不要看 `HEAD`：

```bash
git show --stat 哈希
```

在这份输出里找到 `LayoutTests` 或 `Tests` 路径，打开那个测试文件。用一句话写下它断言的不变量，抄进笔记。

然后：

```bash
git grep -n "函数名" -- Source | head
```

函数名从你刚打开的测试或修复 diff 里抄，必须是完整标识符。对每个调用点只回答一个问题：这次修复加的那项检查，这个调用点有没有。答得出来的写「有」或「没有」。答不出来的调用点，笔记结论选「候选：代码里少了检查，但还没有在运行的系统上看到错误行为」。不写触发页面。

`git log --grep=308675` 没有输出时，Bugzilla 条目仍未公开。改看最近的 CSP 提交：

```bash
find Source -iname '*ContentSecurityPolicy*' | head
git log --oneline -20 -- Source/WebCore/page/csp
```

`find` 的路径和 `page/csp` 不一致时，用 `find` 打出的目录替换 `git log` 最后的路径。打开最新一条提交：

```bash
git show --stat 哈希
```

后面的步骤和上面相同：先写回归测试的那一句不变量，再列出调用点。

通过：笔记里有一句不变量，以及至少一个调用点的「有」或「没有」。结论不是「准备提交」，除非你已经在 L15 的运行页面上看到了 `UNEXPECTED`。只读到缺少检查，结论保持「候选」。

唯一修复：`find` 没有任何输出。克隆不完整。不要改 sparse checkout。跳到 L18，把 L16 留到克隆能打出 `PASS clone` 的那天。

同一份公告里还可以用同样的命令读这些编号，方法不变，一次只读一个：`308906`（CSP）、`309004`（AudioWorklet 里的 CSP）、`309698`（信息泄露）。`309004` 的文件用：

```bash
find Source -iname '*AudioWorklet*' | head
```

## L17 编译 WebKit，并用它打开对照页

只在 L1 打印过「可以做 L17」时做。没有那一行就跳到 L18。

```bash
sudo xcodebuild -license accept
```

这一行会询问 Mac 登录密码。回到提示符且没有报错，就继续。若停在协议正文里，打开 Xcode 点同意，然后从下面这一行开始，不要再运行 `sudo`。

```bash
xcodebuild -downloadComponent MetalToolchain
cd ~/ios-research/WebKit
Tools/Scripts/build-webkit --debug
echo BUILD_EXIT:$?
```

通过：`BUILD_EXIT:0`。

唯一修复，只看第一处错误：

- 错误文字含 `MetalToolchain`：再运行一次 `xcodebuild -downloadComponent MetalToolchain`，然后只再运行一次 `build-webkit`。
- 错误文字含 Xcode 版本：停止 L17。预检已经说明不该编译。
- 其他错误：把第一行错误抄进笔记，停止 L17，去做 L18。

编译成功后：

```bash
cd ~/ios-research/WebKit
Tools/Scripts/run-safari --debug
```

另开窗口运行 L15 的 `serve_controls.sh`，在这个 Safari 里打开那两个地址。通过标准与 L15 相同。

`run-safari` 会设置 `DYLD_FRAMEWORK_PATH`，让 `/Applications/Safari.app` 使用你刚编出来的 WebKit。这是 WebKit 文档里的运行方式。

## L18 读 Firefox iOS 的消息桥

对照物是 L6。你已经见过：`page` 世界里的页面可以调用 `webkit.messageHandlers`，原生侧要用 `frameInfo.request.url` 的 host 决定接不接受。

```bash
git clone --depth=1 https://github.com/mozilla-mobile/firefox-ios.git ~/ios-research/firefox-ios
git -C ~/ios-research/firefox-ios grep -n "WKScriptMessageHandler" -- "*.swift" | head -40
```

克隆失败只重试一次。第二次失败就改在浏览器打开这两个文件，问题相同：

- <https://github.com/mozilla-mobile/firefox-ios/blob/main/BrowserKit/Sources/WebEngine/WKWebview/Scripts/WKContentScriptManager.swift>
- <https://github.com/mozilla-mobile/firefox-ios/blob/main/BrowserKit/Sources/WebEngine/WKWebview/WKEngineConfiguration.swift>

在笔记里回答：

1. `addInPageContentWorld` 把 handler 注册进哪个 content world？
2. `didReceive` 把 `WKScriptMessage` 的哪个字段交给了下一层？
3. 同一个函数里有没有读取 `frameInfo.request.url`？

通过：三句都写下了。第 3 句无论是「有」还是「没有」都算通过。

「没有」时结论选「候选」。不要写一个页面去调用 Firefox 的账号或正式安装包里的 handler。若要报告 Firefox 的问题，先找仓库自己的安全政策：

```bash
find ~/ios-research/firefox-ios \( -iname 'SECURITY.md' -o -iname 'security.md' \) | head
```

按那个文件里的地址报告。没有这个文件，就停在「候选」，不要改寄到 Apple。

## L19 什么时候才提交给 Apple

笔记结论是「可复现的逻辑差异，准备提交」时才提交。练习崩溃、候选、只有崩溃，都不提交。

提交页：用 Apple ID 登录 <https://security.apple.com/>。说明见 <https://support.apple.com/en-us/102549>，奖励规则见 <https://security.apple.com/bounty/guidelines>。网页打不开时，把同一份笔记寄到 `product-security@apple.com`，附件按 <https://support.apple.com/en-us/102148> 加密。邮件无法在网页上追踪进度。

报告里放这四样，都已经在笔记模板里：

- 关于本机里的整行版本，加上 iPhone XS Max
- 观察到的行为，和你预期的行为
- 从干净状态开始的编号步骤
- 页面原文或 ASan 报告原文

奖励规则写明，带可靠利用的报告更容易被评估。本指南的通过线是可复现的行为差异。利用步骤不在这份指南里。fuzz 的原始输出不能单独当报告，Apple 的开源安全说明要求附上能复现的说明：<https://github.com/apple/.github/blob/main/SECURITY.md>。

通过：你能指出笔记里的结论属于哪一类，并且只有「准备提交」会打开上面的网站。
